> Status: the tier-one JWT, Convex Auth, and Better Auth declaration
> resources are implemented under `alchemy/Convex/Auth`. They emit
> deterministic generated-file, env, route, package, component, and
> manifest metadata while keeping secret plaintext out of state.

The Convex integration has three auth tiers because the setup work
and file ownership are genuinely different:

- Tier 1 configures JWT providers only.
- Tier 2 installs full Convex Auth.
- Tier 3 installs Better Auth as a Convex component and generates its route
  plumbing.

Choose the smallest tier that matches the product you are building.

Snippets on this page run inside an `Alchemy.Stack` body and assume
`import * as Config from "effect/Config"`. Redacted environment-variable
values are passed as `Config.redacted("NAME")`; see the
[security model](/convex/concepts/security-model) for the full `SecretInput`
contract.

## Quick comparison

| Tier | Resource | Best for | Generated files | Route ownership |
| --- | --- | --- | --- | --- |
| 1 | `Convex.Auth.Clerk`, `Auth0`, `WorkOS`, `CustomOidc`, `AuthConfig` | Existing JWT identity provider; no auth runtime generated by Alchemy | `convex/auth.config.ts` | None unless you add routes yourself |
| 2 | `Convex.Auth.ConvexAuth` | Teams that want the Convex-native auth package and generated setup | `convex/_alchemy/auth.ts`, `convex/auth.ts`, `convex/http.ts` | Generated Convex Auth routes |
| 3 | `Convex.Auth.BetterAuth` | Teams that want Better Auth providers, sessions, and framework helpers | `convex/_alchemy/betterAuth.ts`, `convex/betterAuth/auth.ts`, `convex/auth.ts`, `convex/http.ts` | Generated `/api/auth/*` by default |

Auth resources are declaration resources. Pass their attributes into your
app/deployer composition when you want Alchemy to converge codegen, env, and
route wiring together instead of relying on hand-maintained auth files.

## Tier 1: JWT provider config

Tier 1 writes provider configuration without taking over your whole auth
story. Multiple resources merge into one providers array. All snippets
below run inside the `Alchemy.Stack` `Effect.gen` body.

```ts
const clerk = yield* Convex.Auth.Clerk("Clerk", {
  frontendApiUrl: "https://clerk.example.com",
});

const workos = yield* Convex.Auth.WorkOS("WorkOS", {
  issuer: "https://api.workos.com",
  applicationID: "convex",
  provisionEnvironment: true,
});
```

Supported Tier 1 resources:

| Resource | Props |
| --- | --- |
| `Convex.Auth.AuthConfig` | Raw `{ providers: AuthProviderEntry[] }` |
| `Convex.Auth.Clerk` | `{ frontendApiUrl, applicationID? = "convex" }` |
| `Convex.Auth.Auth0` | `{ domain, applicationID }` |
| `Convex.Auth.WorkOS` | `{ issuer, applicationID, provisionEnvironment?: boolean }` |
| `Convex.Auth.CustomOidc` | `{ issuer, applicationID }` |

Use Tier 1 when you already know how the rest of your auth routes and user
model should work.

## Tier 2: Convex Auth

`Convex.Auth.ConvexAuth` models the full setup for `@convex-dev/auth`.
It installs the package, generates `convex/_alchemy/auth.ts`, registers the
required routes, and sets provider env vars through deployment resources.

```ts
const auth = yield* Convex.Auth.ConvexAuth("Auth", {
  providers: [
    {
      id: "github",
      type: "oauth",
      clientIdEnv: "GITHUB_CLIENT_ID",
      clientSecret: Config.redacted("GITHUB_CLIENT_SECRET"),
    },
  ],
});
```

Use this tier when you want the Convex-native package and do not need the
full Better Auth component model.

## Tier 3: Better Auth

`Convex.Auth.BetterAuth` is the highest-level auth resource. It wraps the
promoted `BetterAuth` integration, installs
`@convex-dev/better-auth`, wires deployment env, and generates route and
adapter files.

```ts
const auth = yield* Convex.Auth.BetterAuth("Auth", {
  siteUrl: "https://app.example.com",
  convexSiteUrl: "https://app.convex.site",
  secret: Config.redacted("BETTER_AUTH_SECRET"),
  providers: [
    {
      id: "github",
      clientIdEnv: "GITHUB_CLIENT_ID",
      clientSecret: Config.redacted("GITHUB_CLIENT_SECRET"),
    },
  ],
  basePath: "/api/auth",
});
```

Generated surfaces include:

| Path | Purpose |
| --- | --- |
| `convex/_alchemy/betterAuth.ts` | Generated Better Auth runtime bridge |
| `convex/betterAuth/auth.ts` | Better Auth instance and adapter seam |
| `convex/auth.ts` | Public auth entrypoint re-export |
| `convex/http.ts` | Generated HTTP registration under `/api/auth` by default |

The higher-level resource records the provider env contract and generated
route metadata. Application-specific Better Auth plugin choices should stay in
your app declaration instead of being hidden in deployment credentials.

## Environment variables

These values belong in deploy-time resources, not in checked-in
`.env.local` files for production.

| Name | Secret? | Used by |
| --- | --- | --- |
| `BETTER_AUTH_SECRET` | Yes | Better Auth session and token signing |
| `SITE_URL` | No | Browser callbacks and absolute URLs |
| `CONVEX_SITE_URL` | No | Convex plugin wiring |
| Provider client IDs | Usually yes or user choice | OAuth providers |
| Provider client secrets | Yes | OAuth providers |
| `JWKS` and similar optional tuning vars | Usually no, but explicit | Better Auth performance and deployment tuning |

## File ownership and route ownership

| Surface | Ownership contract |
| --- | --- |
| `convex/_alchemy/**` | Alchemy overwrites on codegen |
| `convex/auth.config.ts`, `convex/auth.ts`, `convex/http.ts` | Generated-file ownership; existing conflicting files are refused unless you explicitly adopt generated output |
| `convex/betterAuth/auth.ts` | Generated Better Auth adapter surface |
| `/api/auth/*` | Generated only when a high-level auth resource explicitly owns it |

This is important because auth is one of the few places where generated
public routes are acceptable by default only when the resource explicitly
claims them.

## Commands

```sh
alchemy plan
alchemy deploy
alchemy codegen --check
```

The plan output should make auth readable at a glance:

```txt
Components
  + install @convex-dev/better-auth as components.betterAuth

Secrets
  + set BETTER_AUTH_SECRET      (redacted, create)
  + set SITE_URL                https://app.example.com
  + set CONVEX_SITE_URL         https://acme-prod.convex.site

HTTP
  + /api/auth/*                 generated Better Auth routes
```

## Caveats

- Better Auth user IDs stay inside the component boundary unless your app
  deliberately mirrors them into its own `users` table.
- Generated routes are opt-in. If a component should stay private, do not set
  a public `httpPrefix` or high-level auth route owner.
- Tier 1 is intentionally small. If you want generated auth runtime files,
  choose Tier 2 or Tier 3 instead of piling custom conventions onto JWT-only
  config.
